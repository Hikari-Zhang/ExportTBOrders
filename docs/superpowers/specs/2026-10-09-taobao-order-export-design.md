# 淘宝订单导出 Chrome 插件设计

日期：2026-10-09

## 目标

在用户自己已登录的 Chrome 里，把淘宝「已买到的宝贝」中指定日期范围内的订单导出成表格。一行一件商品，包含商品信息和物流信息。数据只在本机处理，不上传。

## 已确认的选择

- 形态：Chrome 插件（Manifest V3），以「加载已解压的扩展程序」安装。
- 抓取方式：在订单页里复用淘宝自己的接口和当前登录态。不读页面卡片，不自己拼一套独立的 mtop 签名客户端。
- 行粒度：一行一件商品。同一订单的订单级字段在每一行重复。
- 范围：弹窗自选开始日期和结束日期，默认最近 3 个月。结束日含当天 23:59:59。
- 格式：Excel（.xlsx）和 CSV 都支持，导出前单选一种。
- 状态：范围内全部状态都导出。未发货的物流三列留空。

## 架构

插件由四部分组成。

| 部分 | 职责 |
| --- | --- |
| 弹窗 | 日期、格式、开始/取消、进度、日志面板、下载 |
| 订单页脚本 | 只注入「已买到的宝贝」页面。翻页拉订单，逐单查物流，把行数据和日志传回弹窗 |
| 解析 | 纯函数。接口 JSON 变成表格行。不发网络请求 |
| 导出 | 纯函数。表格行变成 `.xlsx` 或带 UTF-8 BOM 的 `.csv`，并生成日志文本 |

权限只包含：

- `https://buyertrade.taobao.com/*`
- `https://trade.taobao.com/*`

订单页地址：`https://buyertrade.taobao.com/trade/itemlist/list_bought_items.htm`。`trade.taobao.com` 上的同一路径同样注入脚本。

弹窗发现当前标签不在这两个订单列表地址上时，不发抓取请求，只提供「打开订单页」按钮。

## 数据流

1. 弹窗把开始日期、结束日期、格式发给订单页脚本。
2. 脚本用 `credentials: 'include'` 请求订单列表，从第 1 页向后翻。
3. 按下单时间筛选。晚于结束日期的订单跳过并继续翻页。遇到早于开始日期的订单后停止翻页。列表按时间从新到旧。
4. 订单状态文案包含「等待买家付款」「待付款」「等待卖家发货」「待发货」「未发货」之一时，不再查物流。其余状态都查物流；查不到则三列留空。
5. 其余订单请求物流接口，两次请求之间间隔 400 毫秒。
6. 每个商品生成一行，连同日志传回弹窗。
7. 弹窗下载表格。同一次运行结束时再下载一份日志文本。

导出过程中按钮变为「取消」。用户点取消，或弹窗被关掉，订单页脚本在下一次请求前停止，不再翻页，也不再查物流。

重复点击开始导出时，进行中的那一次不会再开一轮。

## 接口

### 订单列表

`POST https://buyertrade.taobao.com/trade/itemlist/asyncBought.htm?action=itemlist/BoughtQueryAction&event_submit_do_query=1&_input_charset=utf8`

表单字段：

- `pageNum`：从 1 开始
- `pageSize`：15
- `prePageNo`：上一页页码，第 1 页为 0

成功时响应 JSON 含 `mainOrders` 数组。解析使用这些字段：

| 表格列 | 字段 |
| --- | --- |
| 订单号 | `mainOrders[].id` |
| 下单时间 | `mainOrders[].orderInfo.createTime` |
| 店铺 | `mainOrders[].seller.shopName` |
| 订单实付 | `mainOrders[].payInfo.actualFee` |
| 订单状态 | `mainOrders[].statusInfo.text` |
| 商品名称 | `mainOrders[].subOrders[].itemInfo.title` |
| 规格 | `mainOrders[].subOrders[].itemInfo.skuText` |
| 数量 | `mainOrders[].subOrders[].quantity` |
| 单价 | `mainOrders[].subOrders[].priceInfo.price`。没有该字段时改用 `priceInfo.realTotal`，并记一条警告：该列使用的是商品小计 |

某个字段不存在时，该单元格留空，并写一条警告日志。不因为缺字段丢掉整行。`subOrders` 为空时仍输出一行，商品四列留空。

### 物流

`GET https://buyertrade.taobao.com/trade/json/transit_step.do?bizOrderId={订单号}`

响应按 GBK 解码后再解析 JSON。

| 表格列 | 字段 |
| --- | --- |
| 物流公司 | `expressName` |
| 运单号 | `expressId` |
| 最新物流 | 轨迹里时间最晚的一条说明 |

轨迹数组按这个顺序查找，用第一个存在的数组：`address`、`traceList`、`transitStepInfo`。每条的时间字段按 `time`、`status_time` 取值，说明字段按 `place`、`status_desc`、`desc` 取值。

`expressName` 或 `expressId` 为数组，或响应里有多个包裹对象时，物流公司和运单号各自用「；」拼进同一格。最新物流仍只保留时间最晚的一条。没有轨迹时，最新物流留空。

`isSuccess` 不是 `"true"`，或请求失败时，这一单的物流三列留空，继续后面的订单。物流查询不自动重试。

## 表格

固定 12 列，顺序如下：

1. 订单号
2. 下单时间
3. 店铺
4. 商品名称
5. 规格
6. 数量
7. 单价
8. 订单实付
9. 订单状态
10. 物流公司
11. 运单号
12. 最新物流

单价是商品价格。订单实付是整单实付。

Excel 使用一个工作表，表名「订单」。CSV 使用 UTF-8 BOM，逗号分隔，含逗号、引号或换行的字段按 RFC 4180 加引号。

文件名：

- 完整导出：`淘宝订单_{开始日期}_{结束日期}.xlsx` 或 `.csv`
- 部分导出：`淘宝订单_{开始日期}_{结束日期}_部分.xlsx` 或 `.csv`
- 日志：`淘宝订单_导出日志_{yyyyMMdd_HHmmss}.txt`

日期使用本地时区。

## 异常处理

| 情况 | 行为 |
| --- | --- |
| 不在订单页 | 不发请求。提示打开订单页，并给出按钮 |
| 开始日期晚于结束日期 | 导出按钮不可用 |
| 未登录，或列表响应不是订单 JSON | 立刻停止 |
| 验证码或风控 | 立刻停止，不自动重试。已拿到的订单可以「导出已获取的部分」 |
| 某一页读取失败 | 该页重试 1 次。仍失败则停止翻页。已成功的页可以部分导出 |
| 时间范围内没有订单 | 不下载表格 |
| 某一单物流失败 | 该单物流三列留空，继续 |
| 接口能解析成 JSON，但没有 `mainOrders`，也不是登录页或验证码 | 停止。不改去读页面卡片 |
| 导出中再次点击开始 | 忽略 |
| 点取消或关掉弹窗 | 下一次请求前停止 |

验证码或风控的判定：响应要求打开验证地址、响应不是 JSON 且页面出现验证提示、或 JSON 中带有明确的风控字段。判定成立后停止。不绕过验证码。

## 日志

日志有两个出口，内容相同：

- 弹窗里的日志面板，自动滚到最新一行，本次运行的记录都保留。
- 运行结束时下载同内容的 `.txt`。成功、部分导出、失败停止、用户取消都下载。时间范围内没有订单时也下载日志，不下载表格。

一行的格式：

```text
HH:mm:ss [信息|警告|错误] 消息
```

时间用本地时区，24 小时制。

不写入日志的内容：Cookie、token、签名、手机号、完整收货地址、接口原始正文。可以写入：页码、订单号、下单时间、店铺、商品名、订单状态、物流公司、运单号、最新物流摘要、失败原因、响应的顶层字段名。

下面每条分支都必须打日志。实现时按这张表逐条对照，不能只在弹窗里给一句总提示。

| 时机 | 级别 | 消息 |
| --- | --- | --- |
| 点击导出且日期合法、页面正确 | 信息 | 开始导出。范围 {开始日期} 至 {结束日期}，格式 {xlsx 或 csv} |
| 当前标签不是订单页 | 错误 | 当前页面不是「已买到的宝贝」，已停止 |
| 开始日期晚于结束日期 | 错误 | 开始日期 {开始} 晚于结束日期 {结束}，已停止 |
| 开始读某一页 | 信息 | 正在读取第 {n} 页 |
| 某一页成功 | 信息 | 第 {n} 页返回 {m} 笔订单，其中 {k} 笔在时间范围内 |
| 订单晚于结束日期 | 信息 | 跳过订单 {订单号}，下单时间 {时间} 晚于结束日期 |
| 订单早于开始日期 | 信息 | 订单 {订单号} 下单时间 {时间} 早于开始日期，停止翻页 |
| 没有下一页 | 信息 | 第 {n} 页后没有更多订单 |
| 某一页失败，准备重试 | 警告 | 第 {n} 页读取失败，正在重试。原因：{原因} |
| 某一页重试后仍失败 | 错误 | 第 {n} 页重试后仍失败，已停止翻页。原因：{原因}。已获取 {x} 笔订单 |
| 未登录或登录失效 | 错误 | 未登录或登录已失效，已停止 |
| 验证码或风控 | 错误 | 触发验证码或风控，已停止。请在订单页完成验证后再导出。已获取 {x} 笔订单 |
| 列表 JSON 无法识别 | 错误 | 订单接口返回无法识别，已停止。响应字段：{顶层字段名} |
| 时间范围内没有订单 | 错误 | 时间范围内没有订单，未下载表格 |
| 订单或商品缺字段 | 警告 | 订单 {订单号} 缺少{字段名}，该列留空 |
| 没有单价、改用商品小计 | 警告 | 订单 {订单号} 缺少单价，该列使用商品小计 |
| 未发货，跳过物流 | 信息 | 订单 {订单号} 状态为「{状态}」，未发货，跳过物流查询 |
| 开始查某一单物流 | 信息 | 正在查询物流 {i}/{m}，订单 {订单号} |
| 查到物流且有轨迹 | 信息 | 订单 {订单号} 物流：{公司} {运单号} {最新物流} |
| 查到物流但无轨迹 | 信息 | 订单 {订单号} 物流：{公司} {运单号}，无轨迹 |
| 接口成功但没有物流公司和运单号 | 信息 | 订单 {订单号} 无物流信息 |
| 多个包裹 | 信息 | 订单 {订单号} 共 {p} 个包裹，已合并到同一格 |
| 某一单物流失败 | 警告 | 订单 {订单号} 物流查询失败，物流列留空。原因：{原因} |
| 存在没查到物流的订单 | 警告 | 有 {k} 笔订单没查到物流 |
| 行数据生成完 | 信息 | 共 {订单数} 笔订单，{行数} 行商品 |
| 表格下载完 | 信息 | 已下载表格 {文件名} |
| 日志下载完 | 信息 | 已下载日志 {文件名} |
| 用户点取消 | 警告 | 已取消。已获取 {x} 笔订单，未继续请求 |
| 弹窗被关掉 | 警告 | 弹窗已关闭，导出已取消 |
| 用户导出已获取的部分 | 信息 | 已导出已获取的部分。订单 {x} 笔，商品 {y} 行，文件 {文件名} |
| 完整导出结束 | 信息 | 导出完成 |

进度文字仍然分两段显示在日志面板上方：「正在读取第 n 页，已得到 x 笔订单」，然后「正在查询物流 i / m」。进度文字是摘要，不代替上表里的逐条日志。

## 测试

自动测试不访问淘宝，只覆盖解析和导出：

- 一笔订单两件商品得到两行，订单号、店铺、订单实付、订单状态相同。
- 下单时间等于开始日期的订单保留。早于开始日期的订单不进入结果，并作为停止翻页的信号。
- 晚于结束日期的订单不进入结果，翻页继续。
- 结束日期当天 23:59:59 的订单保留。
- 多个包裹的公司和运单号用「；」连接，最新物流取时间最晚的一条。
- 没有轨迹时，最新物流为空。
- 状态文案包含「等待买家付款」「待付款」「等待卖家发货」「待发货」「未发货」时不产生物流查询。
- 缺字段时单元格为空，并产生对应警告日志。
- 上表每一条日志消息都能由对应输入生成，级别和占位内容正确。
- CSV 以 UTF-8 BOM 开头，列顺序与上面的 12 列一致。

登录态下的一次人工核对：打开订单页，导出最近 7 天，对照页面看行数，打开 Excel，抽一笔已发货订单核对运单号，并确认日志文件里有开始、翻页、该订单的物流记录和「导出完成」。

## 不在本版范围

- 不导出退款明细、发票、收货地址、买家留言。
- 不导出完整物流轨迹，只保留最新一条。
- 不上传到任何服务器，不做账号密码登录。
- 不绕过验证码或风控。
- 接口失效时不自动改成读取页面卡片。

## 验收

在已登录的订单页上选择一段有订单的日期，导出的 Excel 或 CSV 满足：一行一件商品，12 列齐全，已发货订单能看到物流公司和运单号。同一次运行下载的日志覆盖上表中实际发生的每一条分支。未发货订单的物流三列为空。验证码出现时停止请求，并允许把已经拿到的部分导出。
